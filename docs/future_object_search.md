# 향후 과제: 지시에 따라 물체를 찾는 탐사와 물체 지도

> 상태: **아이디어 기록만.** 정한 설계가 아니다. 방식·범위·우선순위는 아직 정하지 않았다 (2026-11-16 기록).

## 1. 지시를 바꿔 가며 "빨리 찾기" (판단 모델 + 프론티어 탐사)

지금 위층 판단 모델은 "전체 지도를 가장 빨리 만들기" 한 가지 지시만 받는다.
앞으로는 지시를 바꿔 **찾을 물체를 빨리 찾는 쪽으로** 후보를 고르게 할 수 있다.

- 지시 예: "불을 찾아", "사람을 찾아", "소화기를 찾아", "비상구를 찾아" 등.
- 찾는 수단: 이미 있는 화재 물체 탐지 모델(YOLO — `docs/detect.md`)이 카메라에서 불·연기·소화기·비상구·사람·문·계단을 알아본다.
- 판단 모델이 할 일: 후보(프론티어 관측 지점) 가운데 **지시한 물체가 있을 법한 쪽**을 고른다.
  지금 입력(로봇 지도, 후보 표, 기억, 후보별 지난 카메라 장면)에 지시 문장과 탐지 결과를 더하는 식으로 생각해 볼 수 있다.
- 잴 것(안): 지시한 물체를 처음 찾을 때까지 걸린 시간·간 거리, 전체 탐사 대비 얼마나 빨라지는지.

## 2. 분할(seg)로 물체를 지도에 등록

물체 분할 모델(YOLO-seg 등)로 찾은 물체를 **지도 위 위치와 함께 등록**해 두고, 나중에 그 위치를 보여 준다.

- 프론티어 탐사 중에도 쓰고, **지도가 이미 있는 상태**(다시 들어온 건물 등)에서도 쓴다.
- 지도가 있으면: "소화기는 어디?" 같은 질의에 등록된 위치로 바로 가거나, 등록이 오래됐으면 다시 확인하러 가는 식으로 쓸 수 있다.
- 탐사 중이면: 등록된 물체를 판단 모델 입력(지도 그림 표시·글)에 넣어 1번의 "빨리 찾기"와 이어진다.
- 참고: 깊이 카메라로 물체를 지도에 찍는 기능(`limo_fire_perception` 의 object mapper)이 이미 있으니 그 위에 쌓을 수 있는지부터 본다.

## 정해야 할 것 (나중에)

- 지시 목록과 우선순위, 여러 물체를 함께 찾을 때의 순서
- 판단 모델에 탐지 결과를 어떻게 넣을지(그림 표시 / 글 / 둘 다), 파인튜닝 정답을 무엇으로 할지
- 물체 지도 저장 형식, 같은 물체를 여러 번 봤을 때 합치는 규칙, 지도가 바뀌었을 때 처리
