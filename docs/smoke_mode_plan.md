# 연기 모드 1 주차 데모 계획 (2026-11-04 ~ 11-08)

라이다·카메라에 천을 씌워도(= 토픽이 끊겨도) 다른 센서로 저장 지도 위를 주행해 목표에 닿는다. 요구사항은
[spec.md "연기 모드"](spec.md#연기-모드), 백로그는 [PB-17·PB-18](backlog.md) (에픽 E6 "연기 모드 주행").
이번 주는 Webots 시뮬에서 재고 검증하는 것이 목표다. 실물은 부품이 준비되는 대로 같은 토픽·프레임으로 잇는다.

> 3 단계 "초음파로 내 위치"는 `smoke_localization: wall`(초음파 벽 맞추기)이다 — [아래 "초음파 벽 맞추기 `wall`"](#초음파-벽-맞추기-wall-2026-11-15).

## 1. 정한 것

- **이번 데모의 주행은 Nav2.** 강화학습 연기 모드(`d686576`, 2026-11-08 뺌)는 연기 속 과제·보상이 아직 없고 CUDA 빌드·학습 전이라 이번 주에 데모까지 못 간다.
  초음파 위치 추정은 Nav2·강화학습이 같이 쓰는 부품이라 먼저 만든다(강화학습 연결은 6 단계).
- **쓰는 센서**: 바퀴 오도메트리 + IMU(지금 달림, 연기 영향 없음) + 초음파 HC-SR04 × 2(앞 범퍼 아래 좌우 ±10°(11-20 3D 출력 막대에 맞춤, 전엔 ±20°), 11-13 실물 설계에 맞춰 3 개에서 바꿈 — 아직 안 달림).
  라이다·깊이·컬러 카메라는 쓰지 않는다(천을 씌운 상황 = 토픽 끊김). 레이더·열화상은 이번 범위가 아니다.
- **센서를 끄는 방법**: 시뮬·실물 공용 "센서 차단 노드"(spec.md 의 센서 열화 주입 노드). Webots 월드는 고치지 않고 토픽을 끊는다.
- **기준선부터 잰다**: 초음파 없이(바퀴 + IMU 만) 얼마나 가는지 먼저 재야 초음파가 얼마나 도움이 되는지 말할 수 있다.

### 초음파 벽 맞추기 `wall` (2026-11-15)

3 단계 "초음파로 내 위치"의 지금 방식. 최근 4 초 메아리를 저장 지도 벽 면에 **지금 추정 근처에서만** 맞추고, **보인 벽에 수직인 방향만** 고친다
(지도 전체에서 다시 찾지 않으니 비슷한 복도로 뛰지 않는다). 추정 불확실성(움직이면 커지고 맞추면 줄어듦)을 사전으로 써서 지도와 조금 다른 물체에 끌려가지 않게 한다.
자세한 동작은 `limo_fire_navigation` README "연기 모드", 결과는 [benchmarks 결과 7](benchmarks/README.md).

| | `hold` (바퀴 + IMU 만) | `wall` |
|---|---|---|
| 네 맵 끝까지 | 8/8 판 | 8/8 판 |
| 추정 오차 평균 | 0.08~0.19 m | 0.06~0.12 m (8 판 중 7 판이 `hold` 보다 작음) |

- 데스크톱 Jazzy 에서 쟀다(로봇 Jetson 디스크가 참). `hold` 최대 오차가 Jetson 결과 5 와 같은 수준(0.25~0.32 m 대 0.27~0.30 m)이라 비교는 된다고 본다.
- **기본은 아직 `hold`.** 시뮬 초음파 모델이 잠정이고(빔 폭·비스듬한 벽 메아리를 실측 안 함), 시뮬 방향 오차가 0 이라 실물에서 얼마나 나은지는 모른다.
  실물 초음파를 달면 `smoke_localization: wall` 로 같은 길을 돌려 `hold` 와 비교한 뒤 기본을 정한다.
- 시뮬 방향 오차 넣기는 못 했다: 방향은 교수님 센서 플러그인(`src/external`, 고치지 않음)이 Webots 관성 장치에서 바로 내고, 이 플러그인은 토픽 이름 바꾸기를 받지 않는다.
  넣으려면 IMU 를 도는 받침에 올리는 proto 방식(로봇 `~/imu_drift.patch`, 11-11, 저장소에는 없음) 같은 것이 필요하다.
- 영상: [창고 hold 대 wall](assets/smoke_warehouse_hold_vs_wall.mp4) (실제 위치·추정 위치·초음파·고친 곳을 지도 위에 그림).
- 연기 모드 감속(앞 초음파 0.6 m 안이면 0.05 m/s) 설정은 `slow.*`.

### 실물 첫 시험과 다음 할 일 (2026-11-20 저녁)

실물 LIMO(Jetson Humble, `main` f718f10 을 `~/limo_fire_ws_smoke07` 에 빌드, ESP32 는 COM 포트 → `real.launch.xml esp32_port:=/dev/serial/by-id/usb-1a86_…`)에서 연기 모드를 처음 켰다.

본 것:
- 초음파 2 개 약 14 Hz·열화상 약 4 장/초 나옴(레이더는 안 꽂음). Nav2 는 Jetson 에서 켜지는 데 약 1 분.
- **연기 모드가 초음파 메아리를 전부 버렸다**: 메아리 시각(ESP32 다리가 받은 시각)이 EKF TF 보다 앞서 "TF 없음, 버림". 그래서 장애물 기억·`wall` 이 초음파를 못 받고
  저장 지도의 벽(가상 스캔)만 믿다 실제 벽에 닿았다(충격 4.5 m/s²). 시뮬은 시각이 맞아 안 드러났다.
- 리모컨을 수동으로 내렸다 올리면 Nav2 가 진행 없음으로 목표를 버린다 → 다시 찍어야 한다(정상 동작).
- 평상시 목표가 "Starting point in lethal space" 로 안 됨: 로봇 15 ~ 30 cm 옆에 남은 장애물 칸(사람·수동 주행 흔적) — 지도 비우기로 풀림.
- 좁은 방에서는 앞 초음파가 늘 0.6 m 안이라 감속(0.08 m/s)에 걸려 계속 느리다.

그날 고친 것(빌드만, **실물·시뮬 재확인 안 함**):
- 메아리 시각의 TF 가 없으면 가장 최근 TF 를 `echo_tf_tolerance`(0.3 s) 안일 때 씀.
- 장애물 기억: 0.5 m(`always_within`) 안 메아리는 지도에 있는 벽이어도 찍음(연기 속 위치가 틀어져도 실제 벽을 피하게), 기억 거리 1.0 → 2.0 m(너무 늦게 봄).
- `carve_margin` 파라미터가 코드에서 빠져 있던 것(값은 기본 0.1 로 같았음).
- 운용 화면(RViz)에 초음파 원뿔·열화상 영상·레이더 표적 묶음 "센서 (ESP32)".

다음 할 일:
1. 실물 다시: 위 수정으로 초음파가 쓰이는지(`/scan_obstacles` 에 지도에 없는 물체, 연기 모드를 끌 때 로그 "기억한 칸"), 속도는 0.2 m/s 로 낮춰서.
   기억 거리 2.0 m·`always_within` 은 시뮬(상자 시험·전체 순찰)로도 다시 확인 — 결과 9 는 1.0 m·없음 기준이다.
2. **연기 모드 위치에 초음파 쓰기**: 실물은 바퀴 + IMU(`hold`)만으로 위치가 틀어진다. `wall`(초음파를 지도 벽에 맞춤)을 실물에서 `hold` 와 같은 목표로 비교
   (`ros2 param set /smoke_mode smoke_localization wall`, 연기 모드를 켜기 전에). 실물 초음파 반사 각도·잡음 측정(real_robot_checklist §3)이 먼저 있으면 좋다.
3. 감속(`slow`)을 지도에 없는 장애물이 가까울 때만 걸게 — 지금은 지도 벽에도 걸려 좁은 곳에서 계속 기어간다.
4. 레이더·열화상으로 사람·불 위치 찾기(카메라·라이다를 못 쓸 때): 열화상 덩어리 방향을 여러 자리에서 모아 불 위치를 교점으로, 레이더 표적 방향에 따뜻한 덩어리가
   있으면 사람으로 확인 → 지도 위 물체로 내서 임무 BT(`/radar/people`·`IsFireDetected`)·조준(`/fire/observations`)·운용 화면에. 계산 머리(`smoke_hazard.hpp`)만
   쓰다 멈춤(저장소에 안 올림). 열화상 좌우(`mirror`)·온도 문턱은 실물로 맞춰야 한다.
5. 평상시 주행(라이다)을 0.7 m/s 로 따로 확인(Nav2 최고 속도를 올렸다). 로봇은 Humble 이라 행동 트리·`costmap_update_timeout` 동작을 실물로 확인.
6. ESP32 udev 이름(`/dev/esp32`) 규칙을 로봇에 넣기 — 지금은 `esp32_port:=` 로 직접 줌.

## 3. 시험 (1·3 단계 공통)

- 맵: Webots 4 개 (`limo_fire_maze`·`office`·`warehouse`·`world`, 저장 지도 `limo_fire_navigation/maps/sim/`).
- 출발: 맵 시작 자리(지도 원점), 라이다로 AMCL 위치를 잡은 뒤 센서를 끊는다.
- 목표: 맵마다 가까운 곳·먼 곳(통로 꺾임 포함) 몇 개. 같은 목표 목록을 1·3 단계에 똑같이 쓴다.
- 잴 것: 목표 도착 여부, 도착 때 참 위치(Webots)와 목표 사이 오차, 추정 위치와 참 위치의 차이(이동 거리별), 충돌.
- 비교: (a) 라이다 켬(평소) · (b) 바퀴 + IMU 만 · (c) 바퀴 + IMU + 초음파. 표는 `docs/benchmarks/` 에.

## 4. 알고 갈 한계

- 초음파 몇 개로는 처음 위치를 스스로 찾지 못한다(점이 너무 적다). 출발 위치를 아는 상태에서 오차를 고쳐 가는 용도.
- 장착 방향이 정확도를 정한다. 11-06 까지는 앞·왼·오른(옆 벽으로 좌우 위치), 11-13 부터 실물 받침대로 앞 좌우 ±20°(둘 다 앞을 봐 옆 벽은 거의 못 봄, 바로 앞 ±12.5° 는 원뿔 사이 빈틈).
- 초음파는 벽에 비스듬히 쏘면 거울처럼 튕겨 값이 틀릴 수 있다 → 시뮬 잡음 모델에 넣고 실물로 맞춘다.
- HC-SR04 정확도 3 mm 는 주로 판매처 숫자라 실측으로 확인한다. 거리·각도 값은 ElecFreaks 데이터시트 기준.
- 바퀴 오도메트리 주행 오차는 아직 안 쟀다(hardware.md "확인할 것"). 1 단계 결과가 시뮬 구동 모델 기준이라는 것을 표에 적는다.
