# 인식 벤치마크

Webots 맵에서 로봇이 순찰하는 동안 YOLO 결과를 장마다 정답과 비교해 지표를 낸다. 결과 표는 이 폴더에 `<날짜>_<맵>.md` 로 쌓인다.

```bash
ros2 launch limo_fire_bringup sim.launch.xml world:=limo_fire_maze benchmark:=true   # 로봇은 RViz 목표·순찰로 움직인다
ros2 service call /perception_benchmark/report std_srvs/srv/Trigger                 # 지금까지 표 쓰기 (끌 때도 씀)
```

## 정답

- Webots 카메라 Recognition 의 **분할 영상**(같은 카메라, 같은 순간)에서 물체마다 보이는 픽셀 = 정답 마스크, 그 범위 = 정답 상자. 가려진 부분은 정답에 안 들어간다.
- `limo_fire_sim` 의 `GtCamera` 플러그인이 `/gt/detections`(상자·클래스·월드 물체 번호)와 `/gt/mask`(물체 번호 영상, `/yolo_detector/mask` 와 같은 형식)를 낸다. 컬러 영상과 시각 도장이 같다.
- 30 픽셀보다 작게 보인 물체는 정답에서 뺀다.
- 맵에 정답을 붙이는 법은 [sim/webots/README.md "인식 정답"](../../sim/webots/README.md#인식-정답).

## 지표

| 수준 | 지표 | 정의 |
|---|---|---|
| 장면 탐지 | P · R · F1 | 운용 문턱(conf ≥ 0.35, 탐지기 설정과 같음)에서 IoU ≥ 0.5 로 1:1 짝지은 TP 기준 |
| | mAP50 · mAP50-95 | 탐지기가 낸 것 전부(벤치마크 때 conf ≥ 0.01). Ultralytics 와 같은 짝짓기·101 점 AP, 정답 있는 클래스 평균 (`det_metrics.hpp`, 학습기와 같은 코드) |
| | 평균 IoU | 운용 문턱에서 맞은 것들의 IoU 평균 (얼마나 잘 덮는지) |
| | 크기별 재현율 | 정답 상자 넓이 < 32² · 32²~96² · > 96² px (COCO 구분) |
| 장면 분할 | 위와 같음 | IoU 를 마스크 픽셀로 잰다. 불·연기는 시뮬 정답이 그림판 사각형(투명 부분 포함)이라 뺀다 |
| 속도 | 처리 장/초 · 지연 | 지연 = 카메라 영상 도착 → 탐지 결과 도착 (벽시계). 처리 비율 = 탐지기가 처리한 장 / 정답 장 |
| 물체 지도 | P · R · F1 · 위치 오차 | `object_mapper` 가 지도에 올린 물체를 월드 데이터 파일 정답과 같은 클래스 1.5 m 안 1:1 로 짝지음 |

  사람은 가까이서 몸 일부만 보이면 놓친다(큼 재현율 0.12), 계단은 맵마다 차이가 크다.
- 물체 지도: 맞게 올라간 것의 위치 오차 평균 0.18~0.33 m. 잘못 올라간 것은 주로 문(덕트호스·벽)과 사람·소화기 중복.
- 속도: 처리 15~18 장/초(정답 장의 93~94 %), 지연 평균 16~20 ms. 시뮬이 실시간보다 느려 영상 자체가 약 20 장/초로 들어온다.

## 한계

- 시뮬 영상이라 실물과 모양·조명이 다르다(특히 불·연기는 사진 그림판). 실물 성능은 학습 데이터 시험셋([detect.md](../detect.md))과 실물 시험으로 따로 본다.
- 정답 등장 수는 "장 × 보인 물체"라 오래 보인 물체의 비중이 크다. 물체 하나하나는 물체 지도 표가 센다.
- 문 정답은 Webots `Door` 모델 전체(문틀 위 벽 0.4 m 포함)라 위아래가 YOLO 상자보다 길다.
- 사람은 정답 색을 셔츠 색으로 넣어서 셔츠가 파랗다 (sim/webots/README.md "인식 정답").

# 주행 벤치마크 (연기 모드)

연기 모드 1 주차 계획([smoke_mode_plan.md](../smoke_mode_plan.md)) 1 단계 기준선. `limo_fire_navigation nav_benchmark` 가 월드 데이터 파일 순찰점을 Nav2 로 차례로 가며
Webots 정답 자세(`limo_fire_sim GroundTruthPose`)와 비교한다. 표는 `<날짜>_nav_<조건>_<맵>.md`·`.csv`. 사용법은 [limo_fire_navigation README](../../src/limo_fire/limo_fire_navigation/README.md#주행-벤치마크-nav_benchmark-시뮬-전용).

- 조건: (a) `lidar` 라이다 켬(평소 AMCL) · (b) `wheel_imu` 연기 모드 — 처음 위치를 라이다로 잡은 뒤 라이다·카메라를 끊고 바퀴 + IMU 만, 속도 한도 0.13 m/s
- 도착 오차 = |정답 − 목표| (Nav2 도착 판정 xy 0.25 m 라 그 안팎), 추정 오차 = |Nav2 자세(map → base_link) − 정답|

## 결과 4 — Isaac Sim 교차 검증: 초음파 반사 기준을 부드럽게 하면? (2026-11-13, 노트북 RTX, Isaac Sim 6.2 + ROS 2 Humble 컨테이너)

결과 3 의 "`sonar` 가 `hold` 보다 부정확하다" 가 Webots 의 초음파 모델(입사각 22.5° 넘으면 메아리 없음) 때문인지 보려고, 다른 시뮬에서 같은 Nav2·`smoke_mode`·`nav_benchmark` 로 다시 쟀다.

한계 (결과의 근거 수준):
- 장면은 저장한 지도(pgm)의 점유 칸을 높이 2.4 m 박스로 만든 것이다. 둥근 덕트 호스 등은 계단 모양 면이 되어 입사각이 실제와 다르다. Webots 월드(벽·물체 원래 모양)와 같은 장면이 아니다.
