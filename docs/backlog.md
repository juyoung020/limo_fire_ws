# 프로덕트 백로그

2026-10-26 · 마지막 갱신 2026-10-26

Scrum 프로덕트 백로그. 위에 있을수록 먼저 한다. 스프린트 플래닝 때 위에서부터 골라 스프린트 백로그로 옮기고, 리뷰 때 상태를 고친다.
설계는 [spec.md](spec.md), 진행 기록은 [progress.md](progress.md), 부품은 [parts.md](parts.md).

## 표 읽는 법

- **우선순위**: Must(시연에 꼭) · Should(점수에 큼) · Could(시간 나면)
- **SP**: 스토리 포인트(상대 크기, 1·2·3·5·8·13)
- **목표**: 중간 = 11/30 중간평가(PPT + 동영상), 기말 = 12/17 Live Demo
- **상태**: 됨 · 진행 · 할 일 · 막힘(이유를 적음)

## 마일스톤과 스프린트

## 완료의 정의 (DoD)

- 코드는 C++/Rust, launch 는 XML/YAML, 파라미터는 `config/*.yaml` ([CLAUDE.md](../CLAUDE.md))
- `colcon build --packages-select <패키지>` 경고 없이 빌드
- Webots 에서 한 번 이상 동작 확인(실물이 필요한 것은 실물에서)
- 결과(수치·영상·스크린샷)를 [progress.md](progress.md) 에 기록
- 커밋·푸시 후 팀 노션 스프린트 보드 갱신
