| 파일 | 내용 |
|---|---|
| `ppo.h` · `ppo.cu` | `PPOConfig`(하이퍼파라미터), `PPO`: 롤아웃 버퍼·GAE·PPO 손실·Adam·KL 적응 학습률·체크포인트 |
| `CMakeLists.txt` | `network/` + `ppo/` 라이브러리(fp32 `explore_ppo`, 검사용 fp64 `explore_ppo64`)와 도구 |

## 빌드

```bash
cmake -S train/explore/ppo -B <빌드> -DCMAKE_CUDA_COMPILER=/usr/local/cuda-13.0/bin/nvcc   # RTX 3060 = sm_86 기본
cmake --build <빌드> -j8
<빌드>/gradcheck && <빌드>/gradcheck --negative && <빌드>/gradcheck --full
<빌드>/toy_train --envs 256 --iters 150 --seed 1 --eval-every 25
<빌드>/toy_train --envs 256 --iters 4 --check-determinism
<빌드>/toy_train --envs 256 --iters 8 --check-resume --ckpt <경로>
<빌드>/bench --envs 2048
<빌드>/cnn_check && <빌드>/cnn_bench
```

## 러너가 부를 API (`ppo.h`, 모든 포인터는 GPU)

```cpp
xppo::PPO ppo(xppo::PPOConfig{/*num_envs=*/2048, ...}, xnet::explore_spec(), seed);
void act(const uint8_t* obs_img /*[N][IMG_SIZE]*/, const float* obs_1d /*[N][POLICY_1D]*/,
         const float* priv /*[N][PRIV], nullptr=0*/, float* actions /*[N][4]*/);   // 학습: 샘플·기록·정규화 갱신
void store(const float* reward /*[N]*/, const int* done /*[N]: 0 진행, 1 종료(선언·충돌), 3 끊김*/);
UpdateStats update(const uint8_t* obs_img, const float* obs_1d, const float* priv); // steps_per_env 번 act/store 뒤, 다음 관측으로
void act_inference(const uint8_t* obs_img, const float* obs_1d, float* actions, int n = -1); // 평균 행동, 선언 = p > 0.5
void save(const std::string& path) const;  void load(const std::string& path);      // 반복 사이에서만
int iteration() const;  float learning_rate() const;  xnet::ActorCritic& ac();
```

- `actions`: 연속 3 은 샘플 원값(자르지 않음, 환경이 [−1,1] 로 자르고 한도를 곱함), 선언은 0/1.
- `UpdateStats`: surrogate·value·entropy(가우시안)·kl·lr·grad_norm(자르기 전)·mean_value·mean_return.
- 체크포인트: 머리(형식·`sizeof(real)`) → 층 이름·크기 목록(구조가 다르면 불러오기 거부) → 가중치·Adam m·v·걸음 수 → 정규화 μ·σ²·개수 → 반복 수·학습률·act 호출 수·씨앗.
  `.tmp` 에 쓰고 이름 바꾸기. 같은 체크포인트에서 이어 학습하면 끊지 않은 학습과 비트 단위로 같다(아래 검증 4).

## 롤아웃 버퍼 메모리 (환경 N, 걸음 T, 샘플 S = N·T)

샘플 하나: 2D u8 34 304 B(IMG_SIZE 그대로) + 정규화된 1D CRITIC_1D 1 336 float(5 344 B — actor 는 앞 1 304 개를 같이 씀) + 행동·log π·가치·μ·로짓·σ·보상·done·이득·이점 17 float(68 B) = **39 716 B**.
N = 2048, T = 24 → S = 49 152 → **1.95 GB** (2D 1.69 GB, 1D 0.26 GB). 2D 를 float 로 두면 4 배(6.7 GB)라 u8 로 둔다.
1D 는 rsl_rl 처럼 정규화된 값을 저장(그때 통계로) — 갱신 중 통계가 바뀌어도 롤아웃 때 본 입력 그대로 다시 쓴다.
그 밖에 Adam m·v 45 MB, 신경망 작업 공간(덩이 1024): actor·critic 각각 0.05 GB(합성곱 융합 커널; 기준 경로는 0.60 GB). 전체는 아래 처리량 절.

### 1) 유한 차분 기울기 검사 `gradcheck` — 통과

fp32 만으로 차분하면 손실 반올림(~1e-7)/h 잡음이 작은 기울기 층(합성곱 편향, |g|~1e-3)에서 상대 오차 1e-2 까지 나왔다(첫 시도, h=2e-3).
h 를 키우면 PPO 자르기·ELU 꺾임에 걸려 오히려 나빠짐(h=1e-1 → 2e-1). 그래서 같은 소스를 fp64 로 한 벌 더 빌드해
**[1] fp64 해석 vs fp64 중앙 차분(h=1e-6)** 으로 수식을, **[2] 학습에 쓰는 fp32 해석 vs fp64 해석**(층의 모든 원소)으로 fp32 구현을 본다.

## 처리량·메모리 (`bench --envs 2048`, obs_layout 실제 크기·무작위 관측, RTX 3060 혼자)

```
환경 2048, 걸음/반복 24 (샘플 49152), 덩이 1024, 에포크 5 × 미니배치 4, 변수 5653096 개 (22.6 MB)
act 한 번 (환경 2048 개, 샘플·기록·정규화 갱신): 47.64 ms
act_inference 한 번: 23.01 ms
update 한 번 (GAE + 5 에포크 × 4 미니배치, 샘플 49152): 12209 ms → 20129 샘플·에포크/s
GPU 메모리: 이 프로세스가 더 쓴 양 3.43 GB (롤아웃·Adam·작업 버퍼 2.06 GB, 신경망 작업 공간 actor 0.60 + critic 0.60 GB, 환경 쪽 관측 버퍼 0.08 GB, 나머지 cuBLAS·CUDA 문맥)
```
→ 반복 하나의 학습 쪽 시간 ≈ 24 × 48 ms + 12.2 s ≈ **13.4 s** (+ 시뮬 걸음). 2 시간이면 약 500 반복(2 400 만 걸음).
(당시) 덩이 2048 은 빠르지 않고(update 12.4 s) 메모리만 4.66 GB 로 늘어 1024 를 기본으로 뒀다 — 합성곱 융합 뒤에는 4096 이 빠르다(아래 "합성곱 융합 커널").

어디에 시간이 드나(nsys, 환경 1024): 합성곱·MLP GEMM ≈ 50 %, 편향+ELU·ELU 역방향 ≈ 25 %, u8→float 재배치 ≈ 11 % — 대부분 메모리 대역 한계(fp32 활성값; 가까운 지도 첫 층 출력 16×32×32 가 가장 큼).
더 빠르게 하려면: 편향+ELU 를 GEMM 뒤에 합친 커널, 활성값 fp16(정합성 검사 다시), 첫 층 4×4 stride 4. 이번에는 안 함.
