# network — 신경망 (2D 관측마다 CNN + MLP, GPU 정방향·역방향)

C++/CUDA 만 쓴다(MLP 는 cuBLAS GEMM, 합성곱 가지는 직접 짠 융합 커널 — cuDNN 은 이 PC 에 시스템 설치가 없어 안 씀).
빌드·검증 도구는 `ppo/CMakeLists.txt` 가 같이 만든다(`ppo/README.md`).

| 파일 | 내용 |
|---|---|
| `common.cuh` · `common.cu` | 오류 검사, 행 우선 GEMM(cuBLAS), 결정적 축소(열 합·전체 합 — 원자 연산 없음). `real` 형(fp32, 검사용 fp64 한 벌) |
| `gemm_fused.cuh` · `gemm_fused.cu` | MLP 용 직접 짠 GEMM + 에필로그 융합 (bf16 텐서 코어 또는 fp32 정확 모드) — 아래 "MLP GEMM" |
| `actor_critic.h` · `actor_critic.cu` | `Net`(CNN 가지들 + MLP), `Normalizer`(1D 실행 평균·분산), `ActorCritic`(actor·critic·log σ 를 변수 버퍼 하나에), `explore_spec()` |
| `cnn_fused.cuh` · `cnn_fused.cu` · `cnn_fused_wr.cuh` | 합성곱 가지 하나(3 층 + 편향 + ELU)를 커널 하나로 — 정방향·역방향, fp32 판(정확 경로)과 텐서 코어 판(워프가 자기 몫을 레지스터 안에서 끝까지, bf16 입력·fp32 누산, 학습 기본) |
| `cnn_tail.cuh` · `cnn_tail.cu` | 합성곱 넷째 층(덧댐 + 2×2 s2 + 편향 + ELU)을 커널 하나로 — 정방향·역방향, fp32 FMA. 아래 "넷째 층" |
| `distribution.cuh` | 행동 분포: 가우시안 3(v, vy, ω) + 베르누이 1(끝 선언) — log π·엔트로피·KL (`__device__`) |
| `graph_net.cuh` · `graph_net.cu` · `graph_policy_cpu.h` | 그래프 어텐션 정책(HEADER 식) — 아래 "그래프 어텐션 정책" |

입력·출력 크기는 `mdp/obs_layout.h` 만 보고 맞춘다(`explore_spec()`).

## 구조

```
                     공유 인코더 (actor·critic 이 같이 씀)
가까운 지도 u8 6×64×64 ─/255→ conv 2×2 s2 16 → 32 → 32 → 32, ELU → 32×4×4 = 512 ┐
먼 지도     u8 7×32×32 ─/255→ conv 2×2 s2 16 → 32 → 32 → 32, ELU → 32×2×2 = 128 ├ F (1024) ─┬→ [F | 정책 1D 1304] → actor MLP 512-256-128 ELU → v·vy·ω 평균 3 + 선언 로짓 1
깊이        u8 1×40×64 ─/255→ conv 2×2 s2 16 → 32 → 32 → 32, ELU → 32×3×4 = 384 ┘            │                                       (log σ 3 개는 상태 무관 변수)
                                    (넷째 층 앞에서 5×8 격자를 0 행 덧대 6×8)            └→ [F | 참값까지 1D 1336] → critic MLP 512-256-128 ELU → 가치 1
```

- 학습 변수 약 276 만 개(11.0 MB, 옛 구조 565 만 개의 반): 인코더 약 6.5 만, actor·critic MLP 첫 층이 2328·2360 → 512.
- **공유 인코더(구조 버전 2, 2026-11-04)**: 합성곱 가지를 actor·critic 이 같이 쓴다 — 한 번만 계산하고, 두 MLP 의 특징 기울기를 더해(고정 순서) 인코더로 흘린다(손실은 지금과 같은 합 손실).
  Stable-Baselines3 의 PPO `CnnPolicy` 기본이 같은 꼴이다("The CNN is shared between actor and critic for A2C/PPO (on-policy algorithms) to reduce computation", SB3 문서 Policy Networks).
  주의: rsl_rl(2.3.1)의 `ActorCritic` 은 actor·critic 을 따로 둔다(공유 아님), 상태 입력 연구(Andrychowicz et al., "What Matters in On-Policy RL", 2021)는 따로 둔 쪽이 낫다고 보고 —
  그래서 학습 곡선을 옛 구조와 같은 조건으로 비교해 확인했다(ppo/README "구조 버전 2").
- **합성곱 4 층**: 해상도 1/16(64→4, 32→2, 40×64→3×4) — 평탄화 3 840 → 1 024, MLP 첫 층 입력 5 144 → 2 328 (actor). 넷째 층 수용 영역 16×16 칸(가까운 지도 1.6 m, 먼 지도 12.8 m).
  깊이 40 행은 16 의 배수가 아니라 셋째 층 뒤 5 행을 0 행 하나로 덧대 6 행으로(덧댄 자리는 입력 0 — 합성곱 0 덧댐과 같은 뜻).
  앞 세 층은 융합 커널(아래 "계산 방식"), 넷째 층은 융합 커널 `cnn_tail`(fp32, 기준 경로 = 덧댄 im2col + cuBLAS sgemm + 편향·ELU, `Net::tail_forward/backward`). 층 수는 4 로 고정(3 층 구조 코드는 지움).
- 체크포인트 형식 버전 2 (층 이름도 `enc.cnn*`) — 버전 1(옛 구조) 체크포인트는 불러오기를 거부한다.
- **MLP [512, 256, 128] · ELU**: legged_gym 기본값 그대로 — `legged_gym/envs/base/legged_robot_config.py:207-209`
  (`actor_hidden_dims = critic_hidden_dims = [512, 256, 128]`, `activation = 'elu'`, [leggedrobotics/legged_gym](https://github.com/leggedrobotics/legged_gym) master, 2026-11-04 확인).
  actor·critic 따로인 것도 rsl_rl `modules/actor_critic.py:42-55`(2.3.1) 와 같다.
- **σ**: 상태 무관 변수. rsl_rl `actor_critic.py:69-72` 의 `noise_std_type="log"` 꼴(`log_std` 변수), 초기 σ = 1
  (`init_noise_std = 1.0`, legged_gym `legged_robot_config.py:206`). tanh 없음 — log π 는 자르기 전 값(mdp/README "행동").
- **선언 로짓 편향 초기값 −7** (actor 마지막 층 편향의 마지막 원소): 걸음마다 뽑으므로 0 이면 판이 평균 2 걸음에 끝난다(mdp/README "행동", 범위 −6~−8 중간).
- **초기화**: torch `nn.Linear`·`nn.Conv2d` 기본(가중치·편향 U(±1/√fan_in) — kaiming_uniform a=√5 와 같은 경계), rsl_rl 은 따로 초기화하지 않는다.
- **CNN: 2×2 stride 2 합성곱 (버전 1 은 3 층·망마다 따로, 버전 2 는 위 공유 4 층), 채널 16-32-32(-32)**
  - 버전 1 의 층 수 3: 해상도를 1/8 로 줄여 평탄화(3840)를 1D(1304)와 비슷한 규모로 뒀다. 버전 2 는 MLP 첫 층(반복 시간의 큰 몫)을 줄이려 1/16. 공간 배치는 평탄화로 MLP 까지 그대로 간다(전역 풀링 안 함 — 지도에서 "어디에" 가 중요).
  - 2×2 stride 2(겹치지 않는 조각): ConvNeXt 의 내려받기 층과 같은 꼴(Liu et al., "A ConvNet for the 2020s", arXiv:2201.03545 — 단계 사이 2×2 s2 합성곱).
    처음엔 3×3 s2 pad 1 로 짰으나 im2col 이 입력을 9/4 배로 불려 메모리 대역이 병목이었다(장난감 환경 1024 개 반복 9.0 s → 2×2 계층 배치 5.3 s). 2×2 로 바꾸면 조각이 안 겹쳐
    아래 "계층 배치"로 복사 없이 GEMM 하나가 된다. 3 층 뒤 수용 영역은 8×8 칸(가까운 지도 0.8 m, 먼 지도 6.4 m); 그 위는 MLP 가 섞는다.
  - 채널 16-32-32: 과제 예시값이자 작은 입력(64×64 이하)용으로 흔한 크기. 첫 층 출력이 활성값 메모리의 대부분(가까운 지도 16×32×32)이라 첫 층을 16 으로 둔다.
  - 잠정: 본 학습 곡선을 보고 바꿀 수 있다(바꾸면 체크포인트가 깨진다 — 층 이름·크기를 체크포인트가 확인한다).
- **정규화**: 1D 관측만, rsl_rl `modules/normalizer.py` EmpiricalNormalization 과 같은 식(eps 1e-2, `(x−μ)/(σ+eps)`, 배치 평균·분산을 개수 비율로 섞음, until 없음).
  통계는 CRITIC_1D 차원 하나로 두고 actor 는 앞 POLICY_1D 차원을 쓴다 — 차원마다 따로 세는 통계라 actor·critic 정규화기를 따로 둔 것과 수학적으로 같다.
  롤아웃 중 `act` 마다 갱신, 평가(`act_inference`)·마지막 가치(`compute_returns`)에서는 안 바꾼다. 체크포인트에 들어간다.
- 2D 는 u8 로 받아 첫 커널에서 /255.

- **계층형 구조(`explore_spec_hier`, 2026-11-08)**: 같은 인코더·MLP, 정책 1D 1360(뒤 56 칸 = 후보 8 × 7), actor 출력 = 상태 임베딩 64 →
  슬롯 머리(`slot_head.cuh`): 슬롯마다 같은 MLP `w2 · ELU(W1 [임베딩 ; 후보 특징 7] + b1)` (은닉 64, 잠정) → 로짓 8 → 가린 범주 분포(ppo/README "계층형"). log σ 없음.
  슬롯 순서와 무관한 가중치라 후보가 몇 번 칸에 오든 같은 점수. fp32/fp64 정확 경로(기울기 검사 `gradcheck --hier`).

### 그림 (Netron)

예전 구조 버전 2 의 그림·ONNX 는 지금 구조와 많이 달라 `archive/explore_net_v2/` 로 옮겼다(2026-11-04). 지금 구조로 다시 만들려면
(Python 없이, protobuf 를 와이어 형식으로 직접 씀 — `network/tools/onnx_export.cpp`):

```bash
cmake --build <빌드> --target onnx_export                                    # ppo/CMakeLists.txt
<빌드>/onnx_export --out /tmp/net.onnx                                         # 모양만 (구조는 explore_spec() 그대로)
<빌드>/onnx_export --out /tmp/net.onnx --ckpt train/explore/runs/<실험>/ckpt/model_latest.bin   # 가중치·정규화 통계까지
# 그림: netron.app 에 끌어 놓고 전체 그래프 화면을 PNG 로 (브라우저 안에서 읽음, 서버로 안 올림)
```

합성곱 가중치는 체크포인트의 `[cout][자식 dy·2+dx][cin]` 을 ONNX `[cout][cin][kh][kw]` 로 바꿔 넣는다(계층 배치 합성곱 = 보통의 2×2 s2 합성곱).
평탄화 순서가 `[픽셀(래스터)][채널]` 이라 Flatten 앞에 NHWC Transpose 를 둔다. 주의: ONNX 쪽 출력을 우리 CUDA 정방향과 수치로 맞춰 본 적은 없다(그림·구조 확인용).

## 계산 방식

- **합성곱 = GEMM 하나 (계층 배치)**: 픽셀을 "부모 조각 순서"(쿼드트리)로, 채널을 맨 뒤에 둔다. 그러면 층 입력 `[n·P_out][4·cin]` 이 그대로 im2col 행렬이고
  출력 `[n·P_out][cout]` 이 다음 층 입력 배치와 같다 → 정방향 `Y = X·Wᵀ`, 역방향 `dW += dZᵀ·X`, `dX = dZ·W` 가 모두 복사 없는 GEMM. u8 입력만 처음 한 번 이 배치로 바꾼다(`k_reorder_u8`).
  합성곱 가중치 배치는 `[cout][자식 2×2][cin]` (체크포인트도 이 순서).
- MLP 는 `[샘플][특징]`. **MLP GEMM** (`gemm_fused.cu`, `Net::mlp_mode` = `PPOConfig::mlp`):
  - 정방향 `Y = ELU(X·Wᵀ + b)` 를 커널 하나로(편향·ELU 가 GEMM 에필로그). 역방향 `dW += dYᵀ·X` 커널이 같은 K 루프에서 편향 기울기 Σ dY 도 더하고,
    `dX = (dY·W) ⊙ ELU'(H)` 커널이 ELU 미분을 에필로그로 곱한다 → MLP 의 편향+ELU·ELU 미분·열 합 커널이 없다. 첫 층 dX 는 CNN 열(3840)만 — 1D 입력 기울기는 안 쓴다.
  - 모드 2(기본) = bf16 텐서 코어(WMMA 16×16×16, 입력을 공유 메모리에 넣을 때 bf16 반올림, fp32 누산·fp32 에필로그). RTX 3060 은 TF32 텐서 코어가 fp32 SIMT 와 최고 속도가 같고(12.7 TFLOPS)
    fp16/bf16·fp32 누산만 두 배(25.5 TFLOPS)라 bf16 을 쓴다. 모드 1 = 같은 타일·같은 에필로그의 fp32 FMA(정확 모드, `gradcheck` 기본). 모드 0 = 옛 cuBLAS sgemm + 따로 커널.
  - 타일: 128×64 블록이 4 물결(SM 28 × 4 = 112) 이상이면 128×64(워프 4 개, 워프당 64×32), 아니면 64×64 — `gemm_bench` 실측으로 정함.
  - 블록이 모자라고 K 가 긴 GEMM 은 split-K (블록 × 조각 ≥ 224, 조각마다 K 타일 4 개 이상, 최대 16): 날값을 작업 공간 [조각][M][N] 에 쓰고 마무리 커널이 조각 순서대로 더한 뒤 에필로그(원자 연산 없음).
    첫 층 정방향(덩이 1024 일 때 128×64 블록 64 개)과 작은 층 dW(K = 덩이 샘플 수 4096, 블록 2~32 개 — 편향 기울기 조각도 같이 모아 더함)에 걸린다.
    `gemm_bench --n 4096`: 512→256 dW 0.179 → 0.103 ms, 256→128 0.169 → 0.042, 128→4 0.179 → 0.022 (편향 기울기 vs host 합 상대 오차 ≤ 3e-7).
  - 가중치 bf16 사본(망마다 `Net::Wh_`, Adam·불러오기·초기화 뒤 `ActorCritic::params_changed()` 가 새로): bf16 정방향·dX 가 W 를 bf16 으로 바로 읽는다(읽는 바이트·레지스터 반).
    반올림이 로더의 즉석 변환과 같아 결과는 비트 단위로 같다(`toy_train` 해시 그대로). `gemm_bench --n 4096`: 첫 층 dX 1.50 → 1.445 ms, 세 층 합 4.75 → 4.66 ms.
    B 레지스터가 반이 되어 큰 정방향·dX(128×128 블록 112 개 이상, K 또는 N ≥ 1024)는 128×128 타일: 첫 층 정방향 1.29 → 1.20 ms(18.0 TFLOPS), dX 1.43 → 1.31 ms(16.5), 세 층 합 4.66 → 4.42 ms.
  - 큰 dW 는 cp.async 2 단(BK 16, 공유 41 KB → SM 당 블록 2 개): fp32 를 레지스터 없이 공유 메모리로 받고 안에서 bf16 으로 바꿔 WMMA. 첫 층 dW 1.46 → 1.29 ms(16.6 TFLOPS), 결과 비트 같음.
  - 큰 dX 도 cp.async(A=dY fp32 2 단 + 변환, B=W bf16 사본은 그대로 3 칸): 첫 층 dX 1.31 → 1.18 ms(18.3 TFLOPS), 결과 비트 같음. 정방향은 1.20 → 1.22 ms 로 이득 없어 그대로. 세 층 합 4.42 → 4.10 ms.
  - 결정성: 타일·K 순서 고정, 편향 기울기는 스레드별 부분합을 고정 순서로 합침(원자 연산 없음) → 같은 입력이면 비트 단위로 같음.
- **합성곱 = 가지마다 융합 커널 하나** (`cnn_fused.cu`): 2×2 stride 2 를 3 번 거친 출력 픽셀 하나는 입력 8×8 조각 하나에만 기댄다(조각끼리 안 겹침).
  그래서 블록이 조각 몇 개(타일)를 맡아 u8 입력을 바로 읽고(/255 는 첫 층 누산 뒤에 곱함) 층 0·1·2 + 편향 + ELU 를 공유 메모리·레지스터 안에서 끝내고 평탄화 결과만 MLP 입력(X0)에 쓴다.
  조각 안은 "부모 조각 순서"(쿼드트리)·채널 맨 뒤 배치라 층 입력 `[행][4·cin]` 이 그대로 im2col 행렬 — 공유 메모리 안에서 복사 없이 다음 층 GEMM 의 입력이 된다.
  - 역방향: 같은 타일을 다시 정방향해(층 0·1 활성값을 전역에 안 둠 — 재계산이 전역 왕복보다 싸다) dW·db 를 블록이 레지스터에 쌓는다.
    출력 기울기는 넷째 층 역방향이 ELU′(출력)까지 곱해 둔 dZ3 를 받는다(F3 를 다시 읽지 않음).
    블록은 상주(격자 = SM 수 × 상주 블록 수, 기기마다 고정)하고 타일을 돌아가며 맡아, 끝에 블록별 부분합 → 블록 순서대로 더함(원자 연산 없음 → 결정적). 첫 층 입력 기울기는 안 구함(u8).
  - **텐서 코어 판(학습 기본, `PPOConfig::cnn_bf16 = true`, `cnn_fused_wr.cuh`, 2026-11-04 update-speed-2)**: `mma.sync m16n8k16` bf16 (fp32 누산), 채널 16-32-32.
    일 단위 = 조각 16 개(셋째 층 출력 행 16 = mma 행 16). 행 순서를 "층 0 행 묶음 (q1, c1) = 16 조각의 층 0 픽셀 (q1, c1)" 로 잡으면
    앞 층 누산기(C 조각)가 그대로 다음 층의 A 조각이 된다(FlashAttention 의 P → A 와 같은 수) — 활성값이 공유 메모리를 거치지 않고, 블록 동기화가 없다.
    층 0 의 k 순서를 [cin][dy][dx] 로 바꿔(가중치를 올릴 때) A 조각 원소 쌍이 입력 한 줄의 이웃 두 바이트가 되므로 u8 입력을 u32 로 바로 읽어 조각을 만든다.
    정방향은 워프가 일 단위 하나를 층 0 → 2 까지(블록 256 스레드, 레지스터 127 → SM 당 워프 16). 역방향은 워프가 (일 단위, q1 사분면) 하나 —
    층 2 출력 기울기는 조각마다 있어 사분면 넷이 서로 기대지 않는다. 워프는 dW2 의 자기 q1 열·dW1 전체·dW0 를 블록 수명 내내 레지스터에 쌓고(레지스터 254, SM 당 워프 8),
    전치가 필요한 곱(dW = Zᵀ·X)은 `movmatrix.trans` 로 C 조각을 A·B 조각으로 바꾼다. 다음 일의 입력·dZ3 는 `cp.async` 로 레인 자기 칸에 미리(레지스터 안 씀).
    끝에 워프 순서대로 더해 블록 부분합 → 블록 순서대로(결정적). 층 0 k 묶음의 뒤 절반이 모두 덧댐이면(cin 6 의 둘째 묶음, cin 1) `m16n8k8` 로 반만.
    반올림 자리는 옛 판(공유 메모리 bf16)과 같다: 활성값·Z 를 bf16 로 반올림해 곱하고 ELU′ 는 반올림된 활성값에서 — 더하는 순서만 다르다.
    실측(덩이 12 288, 세 가지 합, `cnn_bench`): 정방향 6.08 → 3.31 ms, 역방향 9.75 → 7.83 ms (옛 판: 블록 512 스레드가 조각 32 개 타일마다 공유 메모리 왕복·동기화 4·7 번).
    u8 0~255 는 bf16 에 정확히 들어간다. 정밀도: fp64 기준과 상대 오차 합성곱 층 ~1e-2·MLP 층 ~1e-3 (fp32 판은 ~1e-6) — 장난감 학습 곡선은 fp32 판과 같다(ppo/README "속도").
  - **fp32 판** (`cnn_bf16 = false`): 같은 구조를 fp32 FMA 로. 기울기 검사(`gradcheck`)가 이 경로를 본다. 채널이 16 의 배수가 아닌 모양(검사용 작은 구조)도 이 판.
  - 지원 안 하는 모양(층 수 ≠ 3 등)·fp64 검사 빌드는 기준 경로(합성곱 = cuBLAS GEMM, 입력을 계층 배치로 바꾸는 `k_reorder_u8`)로 돈다 — fp64 기준이 융합 커널과 독립인 구현이라 검사가 서로를 본다.
  합성곱 가중치 배치는 `[cout][자식 2×2][cin]` (체크포인트도 이 순서, 융합 커널도 그대로 읽는다 — 형식 안 바뀜).
- MLP 는 `[샘플][특징]`.
- **MLP 은닉 층 = cuBLAS bf16** (모드 2, 2026-11-04 update-speed): 출력 층(폭 4·1)을 뺀 세 층(2 328·2 360 → 512 → 256 → 128)의 정방향·dW·dX 를 `cublasGemmEx`(A·B bf16, C fp32, `CUBLAS_COMPUTE_32F`)로. 출력 층은 융합 커널 그대로.
  직접 짠 커널도 입력(X·W·dY)을 bf16 으로 반올림해 텐서 코어에 넣으므로 정밀도는 같다(fp32 누산, 반올림 `__float2bfloat16_rn` 같음) — 더하는 순서만 다르다.
  이를 위해 입력을 bf16 사본으로 메모리에 둔다: PPO 의 MLP 입력 `[F | 1D]` 의 bf16 사본 `c_xh_`(넷째 층이 F 열을 fp32·bf16 둘 다, 미니배치 모으기·act 가 1D 열을 bf16 으로 씀),
  은닉 출력은 정방향 편향 + ELU 커널(같은 식 `expm1f`)이 fp32 와 bf16 사본(`Hh_`)을 같이 쓴다. 가중치 bf16 사본은 망마다 따로(`Net::Wh_` — 첫 층 W 가 16 B 정렬되게; critic 첫 층은 공용 변수 버퍼에서 8 B 정렬뿐).
  역방향은 층마다 `dy_prep` 커널 하나가 (위 층 dX 날값에 ELU′ 곱하기 — 융합 커널은 dX 에필로그에서 곱하던 같은 식) → dY bf16 사본(`dyh_`) → 편향 기울기(fp32 열 합, 행 묶음 192 개 부분합을 고정 순서로)를 한 번에.
  실측(덩이 12 288 모양, 혼자, 직접 짠 커널 → cuBLAS): 첫 층 정방향 1.98 → 1.33 ms, dW 2.59 → 1.37, dX 0.76 → 0.62 (bf16 최고 25.6 TFLOPS 의 81~87 %; 직접 짠 커널은 45~66 %),
  512→256 정방향 0.30 → 0.18, dW 0.28 → 0.15, dX 0.25 → 0.16 ms.
  결정성: cuBLAS 는 같은 툴킷·같은 구조(SM 수)의 GPU 에서 스트림마다 핸들 하나면 실행마다 비트 같다(cuBLAS 문서 2.1.4 "Results reproducibility") — 같은 씨앗 두 번 체크포인트 같음으로 확인.
- **MLP 입력 버퍼 하나 (복사 없음)**: 인코더 넷째 층이 특징 F 를 PPO 의 MLP 입력 `c_x_ [n][F | 1D]` 의 앞 열에 바로 쓰고(`Net::set_x0`), 미니배치 모으기가 1D 열을 같은 버퍼에 바로 쓴다.
  합성곱 없는 망(actor·critic MLP)은 그 버퍼를 행 간격 그대로 첫 층 입력으로 읽는다(자기 X0 로 복사 안 함). 역방향의 특징 기울기(actor + critic)는 넷째 층 역방향이 두 출처를 읽으며 더한다(`Net::backward_feat`).
  — 예전 `[F | 1D]` 모으기·망마다 X0 복사·특징 기울기 더하기 커널 셋(반복당 ~60 ms 커널 시간)이 없다. 결과는 비트 같음.
- **넷째 층 (`cnn_tail`)**: 행(샘플, 출력 픽셀)마다 F3 의 왼쪽 위 칸 위치·덧댐 여부를 한 번 구해 네 자식을 float4 로 읽는다(덧댄 im2col 행렬을 안 만듦), C·cout 은 컴파일 상수(32·32, 검사용 4·4).
  정방향: 블록 = 행 128 개, 스레드 = 4 행 × 4 채널, 자식 하나씩 공유 메모리로. 역방향: 상주 블록(SM 수 × 상주 수, 기기마다 고정)이 행 32 개 타일을 차례로, 다음 타일 입력을 레지스터로 미리 읽음 —
  dZ = (g_actor + g_critic)·ELU′(Y), dF3 = dZ·W 를 읽은 X 와 같은 자리에 쓰고(앞 세 층이 융합 커널이면 `z_out` 으로 dZ3 = dF3·ELU′(F3) — 같은 fp32 식, 읽어 둔 F3 로), dW·db 는 레지스터에 쌓아 블록 부분합 → 블록 순서대로 더함(결정적). 정밀도는 기준 경로(cuBLAS sgemm)와 같은 fp32.
  `tail_check`: fp64 host 기준 대비 Y·dF3·dW·db 상대 오차 ≤ 5e-7(n 1~4096, 덧댄 깊이 가지 포함), 가지 밖 열·덧댄 칸 안 건드림, 두 번 비트 같음, `z_out` 출력 = dF3·ELU′(F3) 비트 같음.
- **actor ∥ critic 두 스트림**: `ActorCritic::stream2`·`cublas2` 에서 critic 정방향·역방향을 actor 와 동시에(PPO 가 fork/join 이벤트로 잇는다).
  둘은 쓰는 버퍼·기울기 칸이 겹치지 않고 원자 연산이 없어 결과는 한 스트림과 비트 단위로 같다(`toy_train` 해시 같음). 열 합·전체 합의 작업 공간은 스트림마다 따로.
- **결정성**: 원자 연산 없음. 편향 기울기·통계는 고정 순서 두 단계 축소, cuBLAS 는 스트림마다 핸들 하나. → 같은 씨앗이면 비트 단위로 같은 결과(`toy_train --check-determinism`).
- **덩이(chunk)**: 신경망 작업 공간은 `max_chunk` 샘플(기본 = 미니배치 하나, 2048 환경이면 12 288, `PPOConfig::chunk`) 만큼만 잡고, 그보다 큰 배치는 나눠 기울기를 더한다(같은 식 — 더하는 순서만 달라 마지막 비트가 다를 수 있음, 덩이가 같으면 비트 같음).
  작업 공간: actor·critic 각각 0.05 GB (덩이 1024 일 때, 융합 커널 — 합성곱 중간 활성값이 전역에 없음; 기준 경로는 0.60 GB).
- 역방향은 직전 정방향과 같은 `n`·입력으로 부른다(융합 커널은 u8 입력을 다시 읽고 X0 의 층 2 출력을 쓴다).

## 검증 (도구는 `ppo/tools`, 출력은 `ppo/README.md`)

- `gradcheck`: fp64 한 벌(같은 소스, `XNET_FP64`)로 중앙 차분 vs 해석 기울기, fp32 해석 기울기 vs fp64 해석 기울기 — 모든 층 종류(u8 합성곱 첫 층, 합성곱, 선형, ELU, log σ, PPO 손실 커널, 덩이 누적).
- fp32 만으로 직접 차분하면 손실 반올림 잡음(~1e-7/h)이 작은 기울기 층(합성곱 편향 등)에서 1e-3 을 넘어(h 를 키우면 PPO 자르기·ELU 꺾임에 걸림) 기준으로 못 쓴다 — 그래서 차분은 fp64 로 한다.

```
노드 특징 u8 [N][8]  ─ 0 번 칸 = 유효, 1~7 번 /255 ─→ Linear 7 → 128 (initial_embedding)
   → 인코더 층 × 6:  h ← h + MHA(LN(h))  [키 = 자신 + 간선으로 이어진 이웃만, 머리 8, 편향 없음],  h ← h + FF(LN(h))  [128 → 512 ReLU → 128]

   → 포인터: 로짓_k = 10·tanh((s·W_q)·(Hn_k·W_k)/√128), k = 현재 노드의 5×5 스텐실 이웃 24 칸 → 간선 없는 칸을 가린 범주 분포
가치: [E_c | Hc_c | 정규화한 참값 32] → MLP 128 ELU → V   (E_c·Hc_c 는 같은 구조의 가치 몸통 — 기본은 따로, `graph_share` 면 정책 몸통)
```

- **model.py 와 같게 둔 것**: d 128, 머리 8, 인코더 6 층·디코더 1 층, FF 512 ReLU, 정규화 위치(층 앞, pre-LN, eps 1e-5), 디코더가 LN1 을 질의·기억에 같이 쓰는 것,
  어텐션에 편향 없음·머리마다 W_q·W_k·W_v·W_out, 초기화(어텐션 행렬 U(±1/√마지막 차원), `nn.Linear` 기본 U(±1/√fan_in), LN 1·0),
  `current_embedding`(2d → d), 포인터 단일 머리 어텐션 10·tanh(·/√d) 뒤 가림·log softmax, 가치 쪽 인코더를 정책과 따로 두는 것(model.py `QNet`).
- **행동**: `a[0]` = 스텐실 번호 k (0~23, `k' = (dy+2)·5 + (dx+2)`, 가운데 12 뒤는 −1). 간선 비트가 서 있고 그 이웃이 유효한 칸만 고를 수 있다.
  고를 칸이 하나도 없는 샘플은 행동 0·log π 0·엔트로피 0 으로 두고 정책 손실에서 빠진다(계층형 슬롯과 같은 관례).
- **희소 계산**: 입력은 자리 N = gw·gh 개짜리 조밀 버퍼지만 유효 노드만 행으로 모아 계산하고, 인코더 어텐션은 행마다 키 25 개(자신 + 스텐실 24)만 본다 —
  간선 가림을 씌운 조밀 어텐션과 수학적으로 같다(`graph_net_check` [1]). 역방향은 흩뿌려 더하지 않고 키 쪽에서 반대 스텐실로 모아 더한다(원자 연산 없음 → 비트 재현).
  학습 변수는 격자 크기와 무관(같은 체크포인트를 16×16·32×32 어디에나, `graph_net_check` [3]).
- **묶음**: 한 번에 넣는 양은 유효 노드 합 ≤ `graph_rows`(기본 8192, 잠정)·샘플 ≤ `PPOConfig::chunk`(그래프면 기본 1024) 인 연속 구간. 미니배치는 구간들로 나눠 기울기를 더한다.
  그래프 하나의 유효 노드가 `graph_rows` 를 넘을 수는 없다(`graph_rows ≥ gw·gh` 를 생성자가 확인).
- 학습 변수: 따로 2 875 521 개(11.5 MB, 몸통 하나 약 138 만), 공유 1 490 177 개. 체크포인트 형식 3, 블록 이름 `gactor.*`·`gcritic.*`·`critic.*`.

| 가치 쪽이 Q(s, a)(SAC, `QNet`: [E ‖ Hc ‖ 이웃] → 선형 1) 가 아니라 V(s) | 학습을 PPO 로 유지하기로 했다. 몸통(`GraphBody`)은 머리와 분리돼 있어 SAC 로 바꿀 때 Q 머리만 새로 붙이면 된다(`Hn()` 이 이웃 특징을 이미 내준다) |
| 가치 머리가 선형 한 층이 아니라 MLP [128] ELU, 입력에 참값(PRIV 32) | 비대칭 critic(참값)을 쓰는 이 저장소의 관례. 은닉 128 은 잠정 |
| 전역 벡터 GLOB 16 칸을 `current_embedding` 입력에 붙임 | 논문에 없는 우리 추가(배터리·시간 같은 그래프 밖 상태). 그 열의 가중치를 0 으로 초기화해 시작 시점엔 논문 구조와 같은 출력이고, `graph_glob = 0` 이면 아예 없다. 가치 쪽은 GLOB 을 받지 않는다(PRIV 가 포함한다고 보고 — 잠정) |
| 조밀 가림 어텐션 대신 희소(키 25 개) | 환경 2048 개를 12 GB 에 넣으려고. 수학적으로 같다(위) — 단 간선이 5×5 스텐실 안에만 있다는 전제(전작은 `K_SIZE 25` 최근접 이웃) |
| 이웃 = 고정 스텐실 24 칸(자신 제외), 전작은 이웃 목록 25 개(자신 포함) | `mdp::graph` 인터페이스. 제자리 머무름 행동이 없다 |
| 노드 특징 7 칸(dx·dy·유틸리티·지역 길잡이·전역 길잡이·예약 2), 전작 `NODE_INPUT_DIM 4` | HEADER 의 계층 그래프 특징에 맞춘 `mdp::graph` 구성. dx·dy 는 현재 노드 기준 지도 좌표 상대 위치(시뮬이 채움) |
| 노드 덧댐 가림(`node_padding_mask`) 없음 | 유효 칸(특징 0 번)으로 행을 모으니 덧댐 자체가 없다. 무효 노드의 값은 출력에 닿지 않는다(`graph_net_check` [2]) |
| CPU 판이 머리 수를 인자로 받음(기본 8) | 머리 수는 변수 모양에 드러나지 않아 체크포인트에서 알 수 없다 |
| 학습률·배치 등 | PPO 설정(`PPOConfig`)을 그대로 — 전작 SAC 값(LR 1e-5, 배치 128)은 옮기지 않았다 |

### 시뮬 쪽이 맞춰야 할 것 (`xppo::GraphObs`, 모두 GPU 버퍼)

| 버퍼 | 모양 | 뜻 |
|---|---|---|
| `feat` | u8 [환경][N = 1024][8] | 0 번 = 유효(0 이 아니면 유효), 1~7 번은 /255 해서 임베딩 입력. 무효 노드의 나머지 칸은 아무 값이어도 된다 |
| `edge` | u32 [환경][N] | 비트 k = 스텐실 k 번 이웃과 간선. 아래 24 비트만 읽는다. 격자 밖·무효 이웃을 가리키는 비트는 무시. 방향 그래프로 읽는다(a→b 비트만 있으면 a 가 b 를 본다) — 양방향이면 양쪽에 다 세울 것 |
| `cur` | int [환경] | 현재 노드 자리(y·GW + x). **항상 유효 노드여야 한다**(리셋 직후 포함) — 아니면 `act` 가 예외를 던진다 |
| `glob` | float [환경][16] | 정규화 없이 그대로 들어간다 → O(1) 크기로 맞춰 줄 것 |
| `priv` | float [환경][32] | 가치 머리만. 실행 평균·분산으로 정규화(기존 1D 와 같은 식) |

행동은 `act` 가 `[환경][mdp::act::DIM]` 의 0 번 칸에 스텐실 번호를 float 로 쓴다(나머지 칸 0).

### 성능 (RTX 3060 12 GB, 환경 2048 × 걸음 24 = 샘플 49 152, 에포크 5 × 미니배치 4, 그래프마다 유효 노드 평균 150 / 1024·노드마다 간선 평균 9.1)

| | `act` 한 번 | `act_inference` | `update` 한 번 | 반복 하나(act × 24 + update) | GPU 메모리 |
|---|---|---|---|---|---|
| CNN+MLP (`bench`, 기본) | 2.83 ms | 1.23 ms | 0.71 s | 약 0.8 s | 4.18 GB |
| 그래프, 가치 몸통 따로 (기본) | 996 ms | 502 ms | 410 s | 약 434 s | 1.58 GB |
| 그래프, 가치 몸통 공유 (`graph_share`) | 503 ms | 503 ms | 207 s | 약 219 s | 1.15 GB |

- **메모리는 문제가 아니고 시간이 문제다.** 12 GB 에 넉넉히 들어가지만(롤아웃 0.65 GB — 샘플마다 그래프 u8 12 KB, 몸통 작업 공간 0.39 GB × 2) 반복 하나가 CNN+MLP 의 약 500 배다.
  계산량이 그만큼이다: 샘플 하나가 유효 노드 150 행 × (인코더 6 층 × 층마다 약 0.4 MFLOP) ≈ 360 MFLOP — 한 반복의 update 는 49 152 × 5 에포크 × 정·역방향 × 몸통 2 개.
  전작은 SAC 로 걸음마다 그래프 128 개 배치 한 번을 갱신한다(`BATCH_SIZE 128`) — PPO 의 "모은 샘플 전부를 5 번" 과 규모가 다르다.
- 가치 몸통을 따로 두는 것은 메모리로는 감당되고 시간은 꼭 두 배다(공유 207 s vs 따로 410 s).
- 걸음 2·에포크 1 로 줄여 잰 것(샘플 4096, 처리량은 위 전체 측정과 같은 수준 — 따로 560~600 샘플·에포크/s):

| 바꾼 것 | `act_inference` | update 처리량 (샘플·에포크/s) | 몸통 작업 공간 |
|---|---|---|---|
| `graph_rows` 2048 / 4096 / 8192 / 16384 / 32768 | 649 / 541 / 498 / 613 / 626 ms | 474 / 564 / 560 / 489 / 472 | 0.12 / 0.21 / 0.39 / 0.75 / 1.48 GB (몸통 하나) |
| 인코더 1 / 2 / 3 / 6 층 (1 층만 `graph_rows` 4096) | 149 / 198 / 272 / 498 ms | 2230 / 1474 / 1049 / 560 | |
| 2 층 + 공유 | 197 ms | 2725 | |
| 유효 노드 50 / 150 / 300 | 159 / 498 / 1046 ms | 1802 / 560 / 266 | |
| cuBLAS TF32 (`--tf32 1`) | 489 ms | 570 (차이 없음) | |

- `graph_rows` 기본 8192 는 이 표에서 골랐다(잠정). 시간은 유효 노드 수에 거의 비례, 층 수에 거의 비례(고정 몫 약 70 ms).
- 본 학습에 쓰려면 줄여야 한다 — 후보(재지 않은 조합은 위 표로 어림): 공유 몸통, 인코더 층 수, 환경 수·에포크 수, 유효 노드 수(노드 간격), 그리고 구현 쪽으로는 몸통 GEMM 을
  MLP 처럼 bf16 텐서 코어(`gemm_fused`)로 옮기는 것(지금은 fp32 cuBLAS + 직접 짠 어텐션·정규화 커널; 어디가 병목인지는 아직 커널별로 재지 않았다).
